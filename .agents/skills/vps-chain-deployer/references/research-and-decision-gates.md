# 即时研究与推荐门槛

这套流程用于每次用户提出具体选购需求时。供应商注册表只保存入口和核验项；价格、库存、线路表现和条款原文进入本次研究记录。

## 1. 初始化本次记录

在仓库外的私有工作目录运行：

```bash
python3 <仓库路径>/.agents/skills/vps-chain-deployer/scripts/research_gate.py init \
  --topology direct \
  --output research-record.json
```

链式方案把 `direct` 改成 `chain`。脚本会写入带时区的创建时间和所需组件。记录不得包含账号、完整 IP、密码、令牌、私钥、节点链接或付款信息。

## 2. 按来源注册表逐项取证

先读 [provider-matrix.md](provider-matrix.md)。第三方测评只用于发现候选和补充历史体验。结账金额、续费、库存、产品能力和条款必须回到供应商官网。

每条证据都填写：

- `status`：只在亲自打开页面或完成测试后写 `verified`；
- `source_kind`：`live_checkout`、`official_page`、`vendor_console` 或 `network_test`；
- `source`：网页 URL，或仓库外测试文件的 `local-test:<相对路径>`；
- `checked_at`：含时区的 ISO 8601 时间；
- `evidence_excerpt`：支持结论的短原文或打码后的测试输出；
- `value`：给用户看的结构化值。

结账金额、账期、续费和库存证据须在 24 小时内；线路测试须在 72 小时内；其余官网证据须在 7 天内。超过时限重新核验。

线路测试至少记录测试方法、源网络、目标机房、测试时段、延迟和丢包。缺少用户所在网络的实测时，不得用供应商宣传或异地测评替代。

## 3. 记录未确认项

任何页面打不开、字段含糊、客服待回复、线路无法从用户网络测试的情况，都写入 `unknowns`：

```json
{
  "item": "东京机房晚高峰丢包",
  "blocking": true,
  "next_action": "用户在本地 20:00-23:00 对官方测试地址运行 MTR"
}
```

会改变购买选择、实际付款、续费、线路可用性或合规性的未知项必须标记 `blocking: true`。

## 4. 执行硬门槛

填完记录后运行：

```bash
python3 <仓库路径>/.agents/skills/vps-chain-deployer/scripts/research_gate.py check research-record.json
```

退出码含义：

- `0`：推荐门槛通过，可以给出一个明确推荐；
- `2`：证据不完整或已过期，只能报告候选与待核验项；
- `1`：记录格式错误，先修复记录。

Agent 不得手工绕过失败结果，也不得把“候选”“可能适合”“历史上便宜”改写成明确推荐。推荐最多一个，备选最多一个；备选也要单独显示是否通过门槛。

## 5. 对用户输出

先写门槛结果，再写方案：

```text
状态：可推荐 / 未验证
缺少：<门槛输出中的项目；没有则写无>
本次实际付款：<金额、币种、账期>
续费：<金额、周期、自动续费规则>
折算月均：<计算和汇率时间>
线路证据：<用户网络、时间段、延迟、丢包>
限制：<流量、IPv4、退款、用途、协议等>
来源与核验时间：<官网或本地测试记录>
下一步：<购买确认或最小补证动作>
```

研究记录保存到用户私有工作目录。公开仓库只保留空模板和检查程序。
