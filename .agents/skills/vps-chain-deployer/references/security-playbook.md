# 安全执行手册（Agent 内部参考）

## 风险声明顺序

在首次连接和每个高风险变更前，用用户能听懂的话说明：会运行什么、需要什么权限、可能中断什么、如何回退。第三方安装脚本、SSH 登录方式、防火墙、全局路由、TUN、重装和付款都属于高风险步骤。

## 第三方脚本检查

1. 从官方仓库读取当前提交 SHA，禁止直接执行未固定版本的远程脚本。
2. 通过 HTTPS 下载到 root-only 临时路径，记录 SHA-256。
3. 检查脚本及其继续下载的文件，至少搜索 `systemctl`、包管理器、防火墙、SSH、cron/timer、删除操作、遥测和卸载逻辑。
4. 向用户展示来源、提交、哈希、系统影响和回退点，得到确认后才运行。
5. 安装后再次检查监听端口、服务、配置权限和启动状态。

## SSH 与私钥

- 在用户设备生成 Ed25519 私钥并设置口令；Agent 只接触公钥。
- 保留一个已登录的旧会话，验证第二个密钥会话后再改变认证策略。
- 关闭密码登录前验证 `sshd -t`、恢复控制台和备份配置。
- 私钥、UUID、Reality 私钥、完整 VLESS URI、SOCKS5 密码只进用户控制的加密存储。
- 怀疑泄露时先撤销旧公钥/凭据，再继续排查；不要只改节点名称。

## 服务器安全设置

使用 `bash scripts/security_postcheck.sh` 做只读检查。重点确认：

- 只开放用户确认过的端口；没有意外的公网管理面板或未认证 SOCKS5。
- `PasswordAuthentication` 的结果符合用户确认；`PermitRootLogin` 和实际登录方式已记录。
- `/root/.ssh`、`authorized_keys` 和 `/etc/v2ray-agent` 的权限没有对普通用户开放。
- Xray 服务 active/enabled，配置检查通过，重启后仍能恢复。
- 防火墙状态已记录；禁止为追求连通而关闭全部防火墙。

## 回退矩阵

| 现象 | 第一回退动作 |
| --- | --- |
| 加出口后断网 | 停用 SOCKS5 全局路由，恢复直连备份 |
| SSH 改动后无法登录 | 用旧会话或恢复控制台还原 SSH 配置 |
| 节点凭据疑似泄露 | 停用旧节点，重新生成 UUID/Reality 密钥和二维码 |
| 服务器疑似被入侵 | 断开客户端，保存必要证据，从空 VPS 重建 |
| 供应商账户疑似泄露 | 用干净设备改密码、撤销令牌并开启双重验证 |

每次回退后都要重新跑对应验收，不能把“服务重新启动”当成安全恢复完成。
