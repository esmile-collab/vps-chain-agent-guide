# 方案选择器（Agent 内部参考）

这份文件只给 Agent 使用。对用户提问时使用日常语言；不要先让用户选择“直连、链式、SOCKS5、ISP”等技术词。

## 需求挖掘顺序

一次只问一个问题，按用户最容易回答的顺序推进：

| 顺序 | 对用户的问题 | Agent 内部记录 | 继续追问 |
| --- | --- | --- | --- |
| 1 | 每月最多愿意花多少钱？ | 月预算上限、一次性付款接受度、续费敏感度 | 预算是否含固定出口和客户端费用 |
| 2 | 你最怕经常断，还是偶尔慢？ | 稳定性、速度、低延迟的优先级 | 是否能接受临时切换节点 |
| 3 | 平时主要做什么？ | 网页、视频、会议、游戏、下载等场景 | 是否需要 UDP/QUIC、大流量或长连接 |
| 4 | 网站要看到哪个国家？需要长期不变吗？ | 目标国家、固定 IP、IP 类型要求 | 只针对某些网站，还是所有流量 |
| 5 | 你会用哪些设备？ | macOS、Windows、iOS、Android、Linux | 每台设备是否都需要全局代理 |
| 6 | 你愿意维护几台机器？ | 单机、双机、是否接受备用节点 | 能否接受多一层故障和续费 |
| 7 | 你所在地区和网络运营商是什么？ | 用户入口、运营商、IPv4/IPv6 环境 | 是否能做晚高峰测试 |

用户说“不知道”时，解释这个问题影响什么，再给 2–3 个容易选的例子。不要逼用户填写技术字段。

## 常见追问的回答原则

| 用户可能问 | Agent 用一句话回答 |
| --- | --- |
| 为什么不能只看便宜？ | 便宜只说明账单低，线路、续费、流量和 IP 类型仍可能不适合你的网络。 |
| 直连和多一跳有什么区别？ | 直连少一个故障点；多一跳可以换出口国家，但会增加延迟、费用和排查难度。 |
| 家宽/住宅 IP 一定更好吗？ | 它可能更像普通 ISP 出口，但固定性、带宽和平台接受度仍要实测。 |
| 为什么要告诉你我做什么？ | 网页、会议、游戏和下载对延迟、带宽、长连接和 UDP 的要求不同。 |
| 为什么要我自己付款？ | 付款、验证码、条款和自动续费属于你的账号和资金，必须由你确认。 |
| 为什么要重复测试？ | 一次测试只能说明当时状态，稳定性要在不同时间复查。 |
| 你能保证某个平台一直能用吗？ | 不能保证；Agent 只能验证当前线路和 IP 表现，并记录供应商与平台限制。 |
| 我只想让某个网站走美国，能做到吗？ | 可以先评估分流；当前 Skill 的全局链式路径更成熟，分流需要单独确认客户端能力。 |

## 调研动作

收齐需求后再调研，不要先凭经验指定供应商：

1. 从 [provider-matrix.md](provider-matrix.md) 的官方入口和第三方候选入口开始。
2. 读取当天购买页，记录地区、一次性费用、续费、流量、IPv4、退款、用途限制和库存。
3. 对用户所在网络可测试的候选线路做延迟、丢包和晚高峰对比；没有实测就标记为未知。
4. 若需要固定国家 IP，先核对静态性、ASN/组织类型、认证方式、TCP/UDP 和并发限制。
5. 将每个结论标为“页面事实 / 实测结果 / Agent 推断”，给出链接和核验日期。

## 内部方案映射

| 用户目标 | 技术方案 | 当前执行状态 |
| --- | --- | --- |
| 省钱、少维护 | 一台 VPS 直连 | 已支持 |
| 固定某国出口 | 入口 VPS + 认证静态 SOCKS5/ISP | 已支持 |
| 两端都自己控制 | 入口 VPS + 出口 VPS | 仅有原则，部署流程待补 |
| 单点故障不能接受 | 主入口 + 备用入口 | 仅有原则，切换流程待补 |

如果用户选到“部署流程待补”的方案，要明确告诉用户当前 Skill 只能给出计划，不能宣称已完成。

## 给用户的调研结果格式

```text
推荐：<用日常语言描述，例如“买一台日本 VPS，先直接使用”>
原因：<预算、稳定、速度或功能的两条证据>
预计费用：首次 <金额>；续费 <金额>；月均 <金额>
我查过：<供应商链接、测评链接、核验日期>
可能的问题：<线路、IP 类型、UDP、流量或平台限制>
备选：<另一个方案和差异>
你要亲自完成：<注册、付款、验证码、密码输入、最终设备测试>
请确认是否按推荐方案继续。
```

只有用户确认后，才进入购买和服务器变更。
