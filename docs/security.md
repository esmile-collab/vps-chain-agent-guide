# 安全、风险和出问题怎么办

自建节点会涉及服务器管理员权限、SSH 私钥和节点配置。它能减少对公共机场的依赖，也把一部分责任交给你自己。没有“完全不会出问题”的部署，下面写清楚 Agent 会怎么做，以及你遇到问题时怎么退回。

## 你需要知道的风险

| 风险 | 可能发生什么 | Agent 的处理方式 |
| --- | --- | --- |
| 第三方安装脚本 | 脚本可能被改动、下载其他文件或修改系统 | 先看来源，固定提交版本，计算文件哈希，检查会改哪些东西；确认后才运行 |
| SSH 私钥丢失或泄露 | 他人可能登录服务器 | 私钥只在你的电脑生成，使用口令保护，放进密码管理器或加密备份；泄露后立即撤销并重建 |
| 节点链接或二维码泄露 | 他人可以使用你的节点 | Agent 不把完整链接写进聊天、日志或 Git；二维码在本地生成；泄露后重新生成 UUID/密钥 |
| 防火墙或 SSH 改错 | 你可能被锁在服务器外 | 先做只读检查，保留当前 SSH 会话，验证第二个密钥会话和恢复控制台，再关闭密码登录 |
| 全局代理影响设备 | 所有应用的流量都可能经过节点 | 先用普通代理模式测试；开启 TUN、全局代理或路由全部流量前说明影响并等你确认 |
| 供应商或线路故障 | 节点变慢、掉线或 IP 被回收 | 先回到直连或最近一次可用配置，确认账单和服务状态，再决定换线路或新机器 |

## Agent 会做什么

1. 先做只读预检：系统、监听端口、已有服务、SSH 和防火墙状态。
2. 只从用户确认的官方来源下载软件；第三方脚本会记录提交版本和哈希。
3. 每次修改前说明影响、预计中断时间和回退方式。
4. 先建立 SSH 密钥和配置备份，再改 SSH、防火墙、代理路由或重启服务。
5. 部署后运行只读安全检查，确认没有意外暴露的管理端口或未认证 SOCKS5。
6. 先验证入口直连，再接可选出口；链路失败时恢复最近一次直连配置。

## 你要亲自做什么

- 注册、登录、实名认证、同意条款和付款。
- 在网页或本机隐藏输入框输入密码、验证码和 SSH 临时密码。
- 保存私钥和节点配置；Agent 不接收这些完整内容。
- 看到重装、改防火墙、修改 SSH、重启或开启全局代理的确认提示时做决定。
- 在自己的电脑、手机和实际网络上完成最终测试。

## 出问题时按这个顺序处理

1. **只是链路不通**：让 Agent 停用出口链路，恢复最近一次通过验收的直连配置。
2. **SSH 进不去**：保持已有会话不要关闭；用供应商恢复控制台恢复备份的 SSH 配置。
3. **怀疑节点链接或私钥泄露**：停止使用旧配置，从干净设备修改供应商密码，撤销旧 SSH 公钥，重新生成节点凭据。
4. **怀疑服务器被入侵**：先断开客户端和出口，保留必要的日志和账单记录；不要在原机上继续输入新密码。由 Agent 记录现状后，在一台全新的空 VPS 上重建。
5. **供应商或 IP 被限制**：保存检测结果和订单信息，按供应商条款申请更换或退款；不要靠批量换 IP 绕过平台限制。

## 安全验收

- [ ] 私钥在本机或密码管理器中，聊天和 Git 中没有完整凭据。
- [ ] SSH 密钥登录已验证，密码登录的处理结果已记录。
- [ ] 只开放必要端口，没有公开的未认证 SOCKS5 或管理面板。
- [ ] 入口直连和可选出口分别测过，失败时有回退点。
- [ ] 节点二维码和临时文件已在导入后删除。
- [ ] 供应商账号开启了可用的双重验证，续费日期已记录。

这些措施降低风险，不能替你承担当地法律、供应商条款或目标平台规则带来的责任。
